# UF896 (v1.1)

This page records the OpenWrt profile and hardware notes for the **UF896 v1.1**
MSM8916 4G LTE router — the eighth board in the target.

> ⚠️ **Status: not yet validated on real hardware by the maintainers.** We do not
> have a UF896 unit on the bench. The profile builds and its DTS matches the
> stock vendor tree, but boot, modem registration and SIM selection have **not**
> been confirmed end-to-end by us. If you own a UF896, please report results
> (good or bad) in the issue tracker — see [Feedback we need](#feedback-we-need).

## Build identity and storage

- Build alias: `uf896`
- OpenWrt device profile: `generic-uf896`
- DTS: `msm8916-generic-uf896` (patch 867), based on `msm8916-ufi.dtsi`
- Compatible: `uf896,v1.1`
- eMMC: 4 GB class (same as `ufi003`) — the build default GPT is used and
  `flash.sh` reads the real size at flash time, so a mismatch only leaves a
  little unused space
- Recovery partition: **no** (15-partition layout)
- Battery: **none** (batteryless UFI-family stick)

| 8  | `status` red    | shared `led_r`, active-high |
| 9  | `status` green  | shared `led_g`, active-high |

| 77 | `charging` blue | charger indicator |
| 78 | `charging` red  | charger indicator |
| 81 | `wan` blue      | network indicator |
| 82 | `wan` red       | network indicator |
| 83 | `wlan` green    | Wi-Fi indicator |
| 84 | `lan` blue      | data-link indicator |

The three status LEDs live in the shared `leds` node; the six indicator LEDs are
in a separate `leds-extra` node.

## Reset / failsafe button

- GPIO **35**, **active-low, pull-up** — the UF02 / HMUF02-V5 / UFI001B family
  wiring (`button_default` pins `gpio35` + `gpio107`).
- Failsafe mode is enabled by the diffconfig (7 s preinit window,
  `192.168.10.1` on the preinit USB gadget) — see
  [Failsafe](Failsafe/README.md). **Not live-verified on this board.**
- Reminder: a ≥5 s hold that *misses* the 7 s window factory-resets the device.

## SIM

The UF896 does **not** route SIM selection through AP-side GPIOs. Slot 1 is
selected by default and needs no userspace help — a card in slot 1 is detected
and registers with a stock image.

The vendor firmware also accepts `AT+SIMSEL=0,1,1,1` (stock `sim1.sh`), but
that route is **not usable under OpenWrt**: `mmcli --command` requires
ModemManager to run with `--debug`, which the image does not do, and the QMI
plugin does not keep an AT port open for it. The former
`luci-app-uf896-simsel` package (removed in r5) wrapped that command and
could never apply it. If slot-2 selection is ever needed, the supported route
is `qmicli --uim-switch-slot=<n>` — untested on this firmware.

There are no `sim-presence` / `sim_hotplug` GPIO hogs, so **SIM hot-swap is
untested** on this board. See [SIM Hot-Swap](SIM_HOT_SWAP.md).

## Modem bring-up (important)

This board's modem boots into DMS operating mode **`factory-test`** — RF
disabled, no network registration. Stock Android never hit this because its own
init sequence set the mode explicitly.

`/etc/init.d/uf896-modem-online` (START=60, ahead of ModemManager at 70):

1. waits up to 30 s for `/dev/wwan0qmi0`,
2. runs `qmicli -d /dev/wwan0qmi0 -p --dms-set-operating-mode=online`,
3. logs `uf896-modem-online` to syslog.

If the modem never registers, check `logread | grep uf896` first.

## A2 pin — enabled (corrected in r5)

Like HMUF02-V5, UZ801, UF02 and HM-MIFIB-V12, **UF896 sets `qcom,a2-pin`**
(patch `867`, the board DTS). The hold keeps the modem's A2 power domain voted on
(`pm_runtime_forbid()` on `&bam_dmux`), so the AP never releases it.

r4 shipped without the pin on the assumption that this baseband does not hit
the A2 quiesce wedge. **That was wrong.** A field unit with a data bearer up
aborted at ~930 s of uptime:

```
qcom-q6v5-mss 4080000.remoteproc: fatal error received: a2_power.c:1216:A2 Assertion Failed
remoteproc remoteproc0: handling crash #2 in 4080000.remoteproc
```

and then crash-looped every 70–130 s (`a2_power.c:1216` four times, then
`a2_task.c:1185`). The line number differs from the `a2_power.c:1189` seen on
HMU05 because it is a different modem firmware build; the wedge is the same.

The old "field-tested, no assert" note came from a soak that never ran long
enough under traffic to hit it.

## Profile feature selection

| Feature | UF896 |
| :------ | :---: |
| Recovery partition (17-partition layout) | — |
| Power button (`pm8941_pwrkey`) | — |
| Battery / fuel gauge | — |
| SIM hot-swap (`sim_hotplug`) | untested |
| Modem online helper (`uf896-modem-online`) | ✅ |

## Feedback we need

If you have a UF896 v1.1, please report:

1. Does the image boot (serial console / failsafe reachable)?
2. Does `uf896-modem-online` flip the modem to `online`?
3. Does the modem register (`mmcli -m 0` shows `registered` + operator)?
4. Does a card in slot 2 register without any extra command?
5. With the A2 pin enabled (it is, from patch 867), is `dmesg` free of `a2_power` /
   `a2_task` assertions after several hours of data traffic? r4 shipped
   without the pin and aborted at ~930 s; we want confirmation the hold
   keeps it quiet.

Open an issue with the output of `dmesg`, `logread` and `mmcli -m 0`.
