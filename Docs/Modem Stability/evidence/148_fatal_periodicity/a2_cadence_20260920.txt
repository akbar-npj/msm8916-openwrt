=== interpretation ===
pc_irq_count 400 -> 424 over 120 s = 24 edges = 12 collapse/wake cycles
  => ~10 s per cycle during this window (idle, no user traffic)
pc_irq_count is 2 per cycle (assert edge + deassert edge); pc_ack_irq_count matches
  (400 == 400), so every PC edge was acked. pc_resync_count: 0 => no lost edge.

Whole-boot rate: pm_suspend_attempts 202 in ~3322 s => ~16.4 s per wake/suspend cycle.

COMPARISON (Android, stock, live 2026-09-20, from prior session):
  918 modem power-collapses in 54 min => ~3.53 s per cycle.
  => OpenWrt's modem wakes ~4.6x less often than Android's.
CAVEAT: the two runs had different traffic. This is a candidate difference, NOT yet
a causal finding. It needs a matched-traffic comparison before it can be cited.

"quiesced Ns" really is N seconds of CONTINUOUS collapse.

=> the continuous-collapse duration grows across the boot: 60 s chunks early,

rx_tearing_down: 1 while pc_state=0 is BY DESIGN, not a stuck flag:
  - bam_dmux_pm_quiesce() disarms the ring and sets rx_tearing_down (qcom_bam_dmux.c:1475)
  - bam_dmux_power_on() clears it under rx_lock (qcom_bam_dmux.c:1312)
  - the RX watchdog deliberately skips rearming while it is set (qcom_bam_dmux.c:1235)
