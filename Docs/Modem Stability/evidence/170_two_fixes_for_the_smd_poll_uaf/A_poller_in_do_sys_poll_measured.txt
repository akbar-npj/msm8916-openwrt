--- THE TWO ENDS, BOTH MEASURED, AND THEY ARE THE SAME FUNCTION ---
  (a) the poller's ENTRY state: qmi-proxy is inside do_sys_poll on fd 7 =
      /dev/wwan0qmi0  [above]
  (b) the corruption's EXIT state: run A's WARNING call trace is
        __list_del_entry_valid_or_report <- remove_wait_queue
          <- poll_freewait <- do_sys_poll <- __arm64_sys_ppoll
      (Doc 168 run B / Doc 169 run A)

do_sys_poll() is where poll_table_entry objects live (on this task's kernel stack)
and poll_freewait() is the ONLY thing that unlinks them.  So a task observed inside
do_sys_poll is, by construction, holding its entries linked in every queue it
registered -- including channel->fblockread_event.  Freeing the channel while that
task is in do_sys_poll is the use-after-free, and the WARNING above is what it looks
like when the task finally runs poll_freewait().

--- ALSO MEASURED ---
  * qmi-proxy fd 7 on /dev/wwan0qmi0 is the ONLY wwan/rpmsg fd on the device
    (a full /proc/*/fd sweep) -- so the reachable poller set is a set of one.
  * /proc/<pid>/stack IS readable as root for a userspace task on this device
    (it was previously verified only for kernel threads, Doc 168 section 13f).
