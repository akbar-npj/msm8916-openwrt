4. THE MISSING INSTRUMENT -- deployed
-------------------------------------
Nothing on the device answered "what does the kernel print in the last seconds before it
stops?":
  * pstore EMPTY (§8.10);
  * console-ramoops ABSENT, not merely stale;
  * /overlay/q6trace.log (the soak's /dev/kmsg stream) has mtime = boot time => the log
    path is dead (its sibling q6trace.csv IS current, so only the log path died).

Deployed `scratch/dmesg_roll.sh` (autostarted from /etc/rc.local):
  * `dmesg` (ring buffer), NOT /dev/kmsg -- a /dev/kmsg reader sleeps on log_wait when the
    ring is quiet, and a leaked `cat /dev/kmsg | ...` has already cost this project an fd;
  * ONE FILE PER BOOT (/overlay/dmesg_roll_<boot_id>.txt) -- a single rolling file is
    overwritten seconds after the next boot, destroying the pre-hang tail it exists to
    capture (the same self-erasing-instrument bug the beacon had, §8.10);
  * `sync` every write -- the tail must be durable before the stall.
  * keeps only the 4 most recent per-boot files.

Verified live:

               (every 5s, last 250 lines)
