THE ASYMMETRY THAT MAKES THE FIX SAFE (do not "simplify" it away):
  rx_watchdog_work  -> bam_dmux_rx_watchdog_func() TAKES state_lock (:1309).
                       Every caller of power_off/pm_quiesce HOLDS that lock, so the
                       watchdog is already mutually excluded; the sync cancel added
                       only the deadlock.  It re-checks pc_state, in_teardown and the
                       real line level under the lock at :1315-:1317.
  rx_rearm_work     -> bam_dmux_rx_rearm_work_func() does NOT take state_lock
                       (no state_lock site between :1213 and :1261).  It submits RX
                       buffers, so it MUST be drained synchronously before
                       dmaengine_terminate_sync()/dma_release_channel() below.

Doc 164 §5's rule: measure the instrument against the phenomenon before
trusting it.  These five probes are dev_err, so unlike the q6v5 trace they are
NOT free at console_loglevel = 6 -- suppress_message_printing() only suppresses
level >= 6, and dev_err is level 3.  Each one takes the serial console for a
full synchronous write.

  "bam_dmux: SSR teardown T0 scheduled"
      with the "[ts] qcom-q6v5-mss 4080000.remoteproc:bam-dmux: " prefix
      ~95 chars  ->  ~9.6 ms
  T1/T2/T3/T4 (~92-105 chars)  ->  ~9.4-10.5 ms each

  HEALTHY HAND-OFF, for comparison: 7.453 ms
      (from `recovering` to the notifier's `SSR before shutdown` line)
  => T0 alone adds a delay LARGER than the interval it is placed in.

WHY IT IS STILL ACCEPTABLE, precisely:
  * T0 is placed AFTER schedule_work(&dmux->ssr_teardown_work)
      verified in the re-prepared tree: qcom_bam_dmux.c:2434 -> probe at :2441
    so the ~9.6 ms is spent after the work is QUEUED.  The probe cannot prevent
    the teardown work from starting -- which is the one thing T0 exists to
    prove.  It delays rproc_stop()'s continuation only.
  * T1-T4 run in the teardown WORK, which is asynchronous -> off rproc_stop()'s
    critical path.
  * Only dev_err takes the console; the suppressed dev_info lines (:2303, :2444)
    do not, so the probes are not queued behind invisible writers.
