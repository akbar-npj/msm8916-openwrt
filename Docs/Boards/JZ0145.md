# JZ0145

This page records the OpenWrt profile and hardware validation for the **JZ0145
v33** MSM8916 modem stick. Its enclosure looks like the UZ801, but the PCB,
LED wiring and reset GPIO differ. Use the JZ0145 image, not the UZ801 image.

## Build identity and storage

- Build alias: `jz0145`
- OpenWrt device profile: `generic-jz0145`
- DTS: `msm8916-generic-jz0145` (patch 872)
- Board compatible: `jz0145,v33`
- RAM: 512 MB
- eMMC: 7,569,408 sectors × 512 bytes (4 GB class)
- GPT total sectors: 7,569,408
- Recovery partition: **yes**
- Battery: **none**

## LEDs

| GPIO | Function | Note |
| ---: | :------- | :--- |
| 6 | `green:wlan` | Wi-Fi activity |
| 7 | `blue:wan` | LTE / internet status |
| 8 | `red:power` | modem / power status |

All three lines are active-high. The DTS records the stock Android GPIO names
and bench-confirmed colours. The full LED sequence from the board signoff
checklist has not been repeated for the current image.

## Reset / failsafe button

- GPIO **37**, **active-high, pull-down** (idle low), based on the stock
  Android GPIO state.
- A short press during the first 7 seconds of boot entered OpenWrt failsafe on
  the JZ0145 hardware on **2026-11-11**. SSH was available at `192.168.10.1`;
  the system was still in `/etc/preinit` with the squashfs root read-only.
- This confirms the button-triggered failsafe path on this unit. See
  [Failsafe](../Failsafe/README.md) for the procedure.

## SIM

The physical SIM slot is selected by the modem's default pinctrl state:

| GPIO | Stock name | Level |
| ---: | :--------- | :---- |
| 1 | `sim3_switch_gpio` | high |
| 20 | `sim_hotdet_gpio` | low |
| 22 | `sim1_switch_gpio` | low |
| 23 | `sim2_switch_gpio` | low |

These states reproduce stock Android with the physical slot selected. Other
SIM paths are not validated; the JZ02 userspace slot selector does not run on
JZ0145.

No `sim-presence` / `sim_hotplug` node is exposed. In a live test, booting
without a SIM left ModemManager in `sim-missing` state, and inserting a SIM
did not recover the connection. Rebooting with the SIM installed restored
LTE. Insert the SIM before boot; physical hot-swap is **not validated**. See
[SIM Hot-Swap](../SIM_HOT_SWAP.md).

## Profile feature selection

Follows the common baseline:

- Bluetooth software support; radio operation is **unverified**
- WPA3-SAE and multi-SSID support; not separately tested on JZ0145
- CPU CPR and the 800 MHz cap
- Shared Wi-Fi/PMIC cooling maps from `msm8916-ufi.dtsi`
- **A2 power-rail hold** (`qcom,a2-pin` in patch 872)
- Ramoops persistent kernel logging

Leaves out: HMUF02-V5-specific thermal maps, `qcom-time-daemon` and battery
management. The time daemon is restricted to HMUF02-V5 by its init script and
is not selected by the JZ0145 profile.

## Hardware validation

The modem reports baseband
`MPSS.DPM.2.0.c12-00050-M8936FAAAANUZM-1` (2015-08-05). Before the A2 hold,
the original signoff captured 13 modem crashes in about 20 minutes. After
enabling `qcom,a2-pin`, a subsequent run recorded zero crashes at 1,421 seconds
uptime. See the [PR hardware evidence](https://github.com/akbar-npj/msm8916-openwrt/pull/79#issuecomment-6741405509)
and [Modem Stability](../Modem%20Stability/README.md).

Live checks on release `25.12.6-r8`, after rebooting with a SIM inserted, verified:

- Board identity `jz0145,v33`
- ModemManager discovery using the `qcom-soc` plugin and `/dev/wwan0qmi0`
- LTE registration and a connected bearer
- An IPv4 address and default route on `wwan0`
- Three successful pings to `1.1.1.1` and successful `nslookup example.com`

Discovery is not immediate: on the earlier boot without a SIM, ports were
probed around 14 seconds and the modem object became available around 37
seconds. Wait for discovery before capturing `mmcli -L` signoff evidence.

## Recovery hardware test

On **2026-11-11**, the rebuilt recovery image was written to the existing
16 MiB `recovery` partition and read back; the image bytes matched. The device
booted the image with `reboot-recovery -f`. SSH at `192.168.10.1`, USB NCM,
`wlan0` in AP mode with SSID `OpenWrt-Recovery`, and the web UI (HTTP 200) all
worked. A normal reboot returned to production OpenWrt.

The failsafe button and recovery image are now hardware-verified. Remaining
signoff items are the LED sequence, three documented cold boots, a fresh
20-minute modem soak on the current image, and the flashed production-image
checksum. Generate the checklist with
`bash tests/board-profile/signoff.sh jz0145`.
